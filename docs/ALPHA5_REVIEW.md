# alpha.5：採集紀錄、匯入及已證實的操作修正

核對基準是已發布 alpha.4 commit `a5ad0bce773fbcd19ae5a7098b0a28be6881a272`。
先比對發布來源，再決定修改；本文件不是紅隊、安全或全平台相容性認證。

## 外部報告逐項核對

| 說法 | 發布版原碼核對 | 處理 |
| --- | --- | --- |
| 初次啟動預建 Collections，必然再套一層子資料夾 | 不成立。原碼沒有報告所述 loadLocation；預設僅為尚未建立的路徑字串 | 保留原行為，不擴大成自動採用任意空資料夾 |
| 解壓後完整備份可能因繼承寬 ACL 而無法管理 | 條件成立；依實際權限而定，不是所有 D 槽必然失敗 | 明確匯入成新的私人收藏，不更動來源權限 |
| 包內人工範例也是含資料庫的完整備份 | 不成立。包內範例是 HTML 與閱讀資源，沒有 archive.sqlite3；GUI 建立的 Example 是另一份人工收藏 | 分清兩種範例，不以 HTML-only 範例冒充可續抓收藏 |
| 取消建立收藏之前偏好已被寫入 | 成立。folderPath 的寫入早於後續確認；原測試只涵蓋 helper，不涵蓋完整動線 | 選取與讀取路徑不提交偏好；成功接受／開啟後才保存，補完整取消與失敗測試 |
| 每加入一個 ZIP 成員就 FlushFileBuffers | 不成立。Zip::add 沒有 sync；Zip::close 本來就只在最後同步一次 | 不套用不存在的效能修正 |

ZIP 的兩次讀取仍保留：先取得 CRC／大小與 SHA，再於寫出時比對 SHA／大小以偵測來源變動。沒有量測就不能宣稱大收藏匯出更快。

## 採集紀錄不是附件去重的依據

原有 jobs、訊息更新與附件驗證機制已存在。本輪提供可操作的採集紀錄、再次套用選項，以及「更新同識別訊息／不保存對話文字」兩種明確模式。

- 刪除採集紀錄只移除選定已結束作業的歷史列；不刪聊天、附件、blob 或校驗索引。
- 最新收藏狀態與採集選項另行保存，不因刪歷史而把完整性資訊一起抹掉。
- 再次整理會重新讀取選定來源範圍，核對帳號與聊天室身分，沿用 SHA-256／大小吻合的完整附件；不是依檔名略過下載。
- 缺檔、損毀或不同附件版本依實際來源能力處理；不把 UIA 捲動位置、短期 RuntimeId 或部分下載位元組當成可靠續傳游標。
- 套用舊紀錄只設定選項，不自動連線或開始讀取。必須已有相符來源並由使用者再次開始。

## 格式升級

既有格式 1 必須先經明確確認；在私人收藏內建立並檢查獨立資料庫副本後，才以交易升級至格式 2。取消不修改原格式，未知版本拒絕開啟。副本不是附件的第二份備份；升級後不能再用 alpha.4 或更早版本管理同一份收藏。

## 對話文字模式

更新模式按穩定來源識別更新同一訊息，不會因本次沒讀到某筆舊內容就刪除它。

「不保存對話文字」針對 message／thread；已勾選的記事本、留言等其他分類仍依原選項處理。仍可能需要讀取附件所需的識別與關聯；它不是「完全不讀 LINE 控制項」。既有文字保留，新附件必要的父項目只保存最小關聯與省略標記，不保存新訊息正文。離線頁顯示「未保存對話文字」，不冒充收回或刪除。

## 完整備份匯入的界線

匯入對象是已解壓、包含可辨識資料庫的完整收藏，不是任意 ZIP，也不是包內 HTML-only 範例。

匯入資料庫目前有 1 GiB 的有界大小限制，超過時拒絕匯入，不宣稱無限容量。來源保持不動，目的地必須是新建私人位置。資料庫與附件經識別、關聯、大小及雜湊核對；閱讀頁由當前程式重建，不執行或沿用來源提供的任意 HTML／JavaScript。取消或失敗時可能留下私人暫存副本，介面會顯示位置；程式不遞迴刪除未知檔案，確認不需要後可自行清理。目的地碰撞及來源變動需分別驗收；不能為匯入而略過 ACL 或連結檢查。

## 其他已證實的操作界線

- 暫停於 UIA 請求邊界生效；已送出的請求仍保有 35 秒有界期限，停止仍須能中斷。以可控制時鐘的人工測試驗證，不用長時間 Sleep 當作測試。
- 使用者停止採集後，不應再無條件重建整份網頁。已保存內容保留，網頁可能仍是先前版本；之後由使用者明確重建。
- 離線頁顯示最新採集狀態、可知範圍、時間與附件數量，並顯示待補原因。來源範圍未知時明確標示未知，不用「完成」推導全歷史齊全。
- WindowsSource 尚沒有經實機驗證的「附件已過期」訊號；不能把身分／焦點失敗改成可重試來假造完成，也不宣稱真實 LINE 已有自動三次重試或精確過期判別。

完整 ZIP 備份仍要求附件已完整保存；尚有待補或預覽附件的收藏可以閱讀及再次整理，但不能輸出完整備份。本輪未增加部分備份格式。

## 同範疇擴查

依「問題優先、底層擴張、歷史紀錄」順序驗收。本輪再查取消／提交點、暫停／停止傳遞及測試 fixture 約束，不把檢查範圍擴大成未經證實的新功能。

- 匯入新收藏及 ZIP 已發布之後，偏好保存或暫存清理失敗改為明確警告；不把已成功保存的成果報成失敗，也不回頭刪除已發布成果。
- 暫停提示改為「已要求暫停，目前步驟完成後暫停」。連線、探測、社群枚舉與巢狀 UIA helper 請求沿用同一控制；資料列讀取、批次寫入、關聯遍歷、HTML 匯出與 ZIP 中央目錄加入有界取消檢查；不是保證任意 OS 呼叫可立即中斷。
- 匯入惡意路徑測試原先先撞 UNIQUE 約束、沒有抵達預期檢查；改只破壞一筆。資料庫回復測試改確認已進入交易與預期 sentinel，避免前置錯誤造成假通過。
- 格式升級回復測試的快照列舉改只接受真正的 SQLite 主檔，先收集清單再開啟，避免把 WAL／SHM 副檔誤當資料庫。這些是測試修正，不藉此放寬程式防護。

上述新修補仍須在最終來源的 CI 跑完；中途成功不代替最終驗收。

## 驗收與保留限制

本版需對最終來源執行原生核心、採集歷史／去重／文字模式、舊資料格式、匯入、完整取消流程、UIA 暫停、離線瀏覽器與實際封裝 EXE 測試。文件與截圖整合後仍重新建置，不混用前版資產。

通過、失敗、跳過及未測分開記錄。windows-latest、Chromium、合成資料與同程序 DPI 訊息，不等於真實 LINE 採集、實體多螢幕、所有 Windows／瀏覽器／儲存媒體或多 GB 真實工作負載。

EXE 未有 Authenticode 簽章、CFG 未啟用；沒有宣稱消除 SQLite VFS、祖先目錄替換或所有同帳號程序競態。可攜收藏仍沒有加密，私人 ACL 不是加密。請保留原始資料與第二份副本。
