# 直接讀取 LINE 本機資料庫

原生資料庫來源由 alpha.8 提供；本說明的「自動抓取」、批次選擇與 TXT 匯出需使用 alpha.10 或更新版本。alpha.10 已發布；本次建置、Windows 測試與公開下載核對見 [alpha.10 核對紀錄](ALPHA10_REVIEW.md)。已發布的 alpha.9 與更早版本不會被覆寫。

在 Windows 上保持 LINE 登入，開啟 `ChatAtlas.exe`，即可自動尋找常見位置的 `.edb`，或批次指定來源，讀取本機已同步的對話，再使用已核對 LINE 程序中實際讀到的登入工作階段，嘗試取回圖片和檔案。不需要先操作 LINE 的「儲存聊天」、手動匯出文字，也不需要 Python、Node.js、MCP、JSON 匯出步驟或另外安裝解密套件。

```text
已登入的 Windows LINE
  → 自動尋找或批次選擇來源，在記憶體中取得候選金鑰並逐份核對
  → 唯讀讀取本機聊天室、對話與附件資訊
  → 以實際觀察到的登入工作階段及訊息識別呼叫原生附件 API
  → 取回圖片／檔案，失敗時保留待補狀態
  → TXT 對話紀錄、離線閱讀頁與知識地圖
```

資料庫解密程式碼已靜態編入 EXE。這條路徑參考了 [line-summary](https://github.com/yung13yubabie/line-summary) 的本機資料庫讀取方式，但不會載入或執行該專案，也不需要它的 Python 環境。

## 自動抓取

1. 在同一台 Windows 電腦開啟 LINE 並登入自己的帳號。
2. 開啟 alpha.10 或更新版本的 `ChatAtlas.exe`，確認「收藏保存位置」、訊息期間與文字保存方式。日期留空時讀取來源本機可用的期間；結束日包含當天。
3. 按首頁「自動抓取」。程式會尋找 `%LocalAppData%\LINE\Data\db` 及其下最多兩層子資料夾中的非空 `.edb` 候選，排除已知的相簿、Keep 與聊天統計資料庫；最多核對 64 份，不會掃描整台電腦。
4. 程式會略過不可讀、重複或不支援的來源，直接整理所有可讀來源的全部聊天室，嘗試下載對話與討論串附件，再產生 TXT 與離線頁。這個模式使用目前日期及文字設定，不使用手動聊天室或內容類型勾選；相簿、記事本仍不支援。
5. 完成後查看可讀／略過來源數量、TXT 位置，以及離線頁的附件狀態。完整原檔、只有預覽和未取得會分別標示；達到尋找範圍或數量上限時，可改用批次選擇處理其他來源。

第一次核對可能需要較長時間，可以暫停或停止，不需另開命令列或手動輸入金鑰。附件下載期間請保持原 LINE 程序開啟；若提示缺少附件工作階段，可先在 LINE 開啟該附件後重新連接。停止時已採集完成的內容可能保留，不代表整批已完成。

## 批次選擇來源與聊天室

若要限定來源或聊天室，按首頁「批次選擇資料庫…」。候選清單顯示完整路徑，支援勾選、「全選」與「清除」；確認後按「批次連接」。也可手動選擇，檔案視窗優先開啟常見 LINE 位置，支援 Ctrl／Shift 多選 `.edb`／`.db`，一次最多 64 份。

列出聊天室後，依名稱與「來源」欄確認要保存的內容，勾選聊天室、設定期間與文字保存方式，再按「開始整理與更新」。副檔名符合不代表是可讀的 LINE 對話資料庫，仍須通過金鑰、檔案識別與資料表檢查。

每份資料庫各自保留原本的來源與聊天室識別，不把相同名稱、訊息 ID 或同一把金鑰的不同來源合併成一個帳號。清單中的來源編號及檔名只用來區分檔案；可讀資料庫可能是歷史副本，**不能認定全部就是目前登入帳號**，也不代表其附件必定能以目前工作階段下載。再次以單庫或批次整理同一來源，仍沿用原本的收藏識別。

## TXT 對話紀錄

自動抓取與手動開始整理後，都會為選定聊天室各產生一份 UTF-8 TXT，存放於收藏內的 `text-exports/<本次匯出批次>/`。檔名由安全處理過的聊天室標題及完整收藏識別組成，批次另附完成與校驗清單。每次建立新批次，不覆寫先前 TXT；文字匯出期間取消時，不會發布新的完成批次。TXT 已完成後，若在後續步驟停止，這批文字檔仍會保留。

TXT 包含收藏中已保存的對話／討論串文字、時間與發話者，以及附件名稱和經核對的保存狀態。附件原檔仍放在收藏中，不嵌入 TXT；只取得預覽或未取得時會明確標示。TXT 不含登入資料、資料庫金鑰或媒體金鑰。

**TXT 的範圍是本次選定聊天室在收藏中所有已保存的對話／討論串，可能包含先前整理內容，不限本次日期。** 日期欄位限制本次抓取，不會刪除收藏裡的舊文字。選擇「不保存新對話文字」時，TXT 不會因此補回未保存的新文字，先前已保存的文字仍可能出現。這是聊藏產生的文字紀錄，不是自動操作 LINE 內建匯出的格式。

TXT 是另存於收藏資料夾的新匯出；既有「完整收藏 ZIP」不包含 `text-exports`。需要保留或分享 TXT 時請另外複製所需匯出批次，資料庫、媒體與 HTML 的完整備份規則不變。

## LINE 來源與收藏保存位置

| 畫面中的選擇 | 用途 |
| --- | --- |
| 自動尋找或批次選擇的 `.edb`／`.db` | LINE 已有的來源資料庫，程式逐份核對後唯讀開啟以取得聊天室。 |
| 「收藏保存位置」 | 聊藏保存對話、附件、TXT 與離線閱讀頁的資料夾。 |

不用自己建立 `.db` 或 `.edb`，也不要把收藏自己的 `archive.sqlite3` 當成 LINE 來源。不要把 LINE 來源檔放進「收藏保存位置」欄位；這個欄位需要的是你希望收藏存放的資料夾。尋找候選只查看常見位置的檔案資訊，後續才逐份核對解密與資料表，不會修改 LINE 資料。

不必先把圖片或附件下載到另一個資料夾，也不需要先選取附件資料夾。這個來源不需要 `connection.local.json` 或 LINE 版面設定，不依賴視窗捲動或 LINE 內建的儲存聊天選單。原有 UI Automation 仍保留在進階連線頁，屬於另一條來源路徑，不能把這次原生資料庫流程當成它已完成適配的證據。

連線時只讀取目前 Windows 使用者、目前桌面工作階段內且簽章發行者已核對的 LINE 程序，不會自動提升系統管理員權限或注入 LINE。批次共用每個已核對程序的一次金鑰掃描，將候選金鑰逐份核對資料庫；附件則使用匹配來源的同一個 LINE 程序內，有欄位名稱標記的登入 token、應用程式資訊與可辨識的 OBS 登入資訊，不把不同程序的金鑰與工作階段混用，也不憑任意記憶體字串組造憑證。這些登入資料、資料庫金鑰與媒體金鑰只保留在記憶體中，不寫入偏好設定、收藏、TXT、HTML 或診斷輸出。

## 只在 LINE 裡看得到的圖片與附件

**目前尚不能保證取得所有僅能在 LINE 內開啟、未另存到電腦的媒體。** 原生資料庫與登入附件 API 路徑已接上，但目前 Windows LINE 的實際工作階段記憶體、媒體金鑰與伺服器回應，仍需真實版本資料驗證。能開啟 `.edb` 不等於每一個附件都能取得。

自動取回由 C++ 直接使用 Windows WinHTTP 呼叫 LINE 的附件服務。一般媒體依資料庫內的訊息 ID 與已知的 talk／社群服務格式讀取；E2EENext 媒體則使用實際訊息內的服務與物件識別。程式也可沿用訊息實際提供的下載／預覽網址。需要附件授權時，使用同一個已核對 LINE 程序中的實際工作階段，取得或沿用 LINE OBS 附件 token，不要求使用者提供另一個帳號或安裝其他工具。

讀取到的工作階段會綁定原 LINE 程序；該程序結束時不繼續沿用。找不到可辨識的登入欄位、缺少應用程式資訊，或伺服器拒絕授權時，附件會列為未取得。程式不製造登入 token、不停用 HTTPS 憑證驗證，也不沿用瀏覽器或其他程式的 cookie。這個步驟會使用網路；已產生的離線閱讀頁仍可離線開啟。

若訊息同時保留可辨識的 E2EENext 媒體金鑰資訊，程式會在取回密文後先核對完整性，再以 Windows 原生加密元件解密。這需要實際媒體物件資訊與有效媒體金鑰同時存在；不會用資料庫金鑰猜測圖片金鑰。媒體金鑰與原始加密資訊不寫入收藏或離線頁。

- 成功取回完整原檔：保存原始位元組，計算雜湊，沿用去重、完整性檢查、離線預覽與另存流程。
- 只能取得預覽：以縮圖／預覽處理，不列為完整原圖。
- 缺少可辨識的登入工作階段、授權遭拒、附件已過期或缺少可用解密資訊：保留訊息與附件的待補狀態，不假裝已保存原檔。
- 部分 Windows LINE 圖片快取使用 `.eimg` 等另外加密的格式，其金鑰與 `.edb` 資料庫金鑰不同。目前沒有已驗證的完整快取索引與解密流程，不會把這類快取直接改名當成原圖。

自動取回失敗不代表 LINE 畫面內的圖片已不存在，也不代表使用者應先安裝 Python 或其他套件。這表示目前程式尚未取得該附件所需的可用資料，不能把這項限制描述成已完成「LINE 裡可見的圖片全部保存」。

## 可選：日後補入原檔

若之後自行透過 LINE 的另存功能取得原檔，可在「我的收藏」按「補入圖片與附件原檔」，選取待補的那一筆附件，再選擇對應檔案。程式會核對可用的大小與內容資訊，複製進收藏並重新產生離線頁。

這是手動補件功能，不是連接資料庫的前提，也不能當成尚未另存媒體的自動取得功能已完成。程式不會因檔名相同，就把資料夾內任意檔案自動配給訊息。

## 保存範圍

| 內容 | 本機資料庫來源的處理方式 |
| --- | --- |
| 本機已同步的文字訊息 | 保存原文、時間、訊息 ID、發訊者 ID 與可用顯示名稱。 |
| 圖片、檔案等附件訊息 | 保存附件資訊；使用實際訊息識別與已觀察到的登入工作階段呼叫附件 API，嘗試取回原檔／預覽，無法取得時列為待補。 |
| 社群討論串 | 保存範圍內的回覆與原始討論串識別；不保證取得期間外的根訊息。 |
| 相簿、記事本與其留言 | 尚未涵蓋，不能由這個來源選項宣稱保存完成。 |
| 已過期、未同步的對話及不在本機的歷史 | 不另外回補；本機範圍完成不代表完整 LINE 備份。 |

再次整理同一份來源與收藏時，相同訊息識別會更新，已保存且校驗通過的附件會沿用。來源識別同時綁定資料庫位置與實際檔案識別；讀取途中若原檔被另一份資料庫取代，會停止，而不把新內容混入原來源。搬移或替換資料庫前，請先核對收藏與來源。

來源資料庫使用唯讀連線；程式不修改 LINE 的資料表、快取或檔案權限。收藏自己的 `archive.sqlite3` 與附件仍沒有加密；請勿把真實資料庫、收藏、程序記憶體或私人檔案上傳到 Git、issue 或 Release。

## 格式與驗證界線

本機來源依目前已知的 Windows LINE `_chat`、`_message` 與相關資料表讀取，資料庫解密明確使用與 wxSQLite3 相容的 AES-128-CBC。LINE 更新後若金鑰位置、加密方式、資料表或快取格式變更，程式可能明確停止；不要把讀取失敗解釋成聊天室沒有內容。

開發測試使用人工加密資料庫、程序候選、附件及 API 協定回應，驗證唯讀讀取、去重、日期範圍、取消、授權解析與檔案狀態。這些不會連接真實 LINE，也不能代替目前 LINE 版本與「只在 LINE 開啟、未另存」圖片的實機驗收。測試是否已通過，以這次 PR／提交的實際 CI 紀錄為準，不沿用先前 JSON 匯出橋接的結果。
