# 直接讀取 LINE 本機資料庫

原生資料庫來源由 alpha.8 提供，自動抓取、批次選擇與 TXT 由 alpha.10 提供。本說明以 alpha.11 的工作台、逐檔結果及離線閱讀流程為準；alpha.11 仍在本輪建置與驗證中，公開版本與來源見 [Releases](https://github.com/yung13yubabie/chatatlas-offline/releases)。既有版本不覆寫，前版測試不當成本版通過證據。

在 Windows 上保持 LINE 登入，開啟 `ChatAtlas.exe`，即可自動尋找常見位置的 `.edb`，或批次指定來源，讀取本機已同步的對話，再以同一個已核對 LINE 程序中實際讀到的登入工作階段嘗試取得圖片、影片與檔案。不需要先操作 LINE「儲存聊天」、手動匯出文字，也不需要 Python、Node.js、MCP、JSON 匯出或另外安裝解密套件。

```text
已登入的 Windows LINE
  → 尋找或批次選擇來源，在記憶體中取得候選金鑰並逐份核對
  → 唯讀讀取本機聊天室、完整訊息與檔案資訊
  → 使用同一程序的實際登入工作階段嘗試取得原檔／預覽
  → 逐檔記錄結果，產生 TXT、離線閱讀頁與關聯地圖
```

解密程式碼已靜態編入 EXE。此路徑參考 [line-summary](https://github.com/yung13yubabie/line-summary) 的本機資料庫讀取方式，但不載入或執行該專案，也不需要它的 Python 環境。

## 自動抓取全部

1. 在同一台 Windows 電腦開啟 LINE，登入自己的帳號。
2. 開啟 `ChatAtlas.exe`，確認「儲存位置」及「保存設定」。預設完整保存訊息；日期留空會讀取來源本機全部可用期間，結束日包含當天。
3. 在「聊天室」按「自動抓取全部」。程式尋找 `%LocalAppData%\LINE\Data\db` 及其下最多兩層子資料夾中的非空 `.edb` 候選，排除已知相簿、Keep 與聊天統計資料庫，最多核對 64 份，不掃描整台電腦。
4. 程式略過不可讀、重複或不支援的來源，整理全部可讀來源的聊天室，嘗試取得對話與討論串中的圖片、影片及檔案，再產生 TXT 和離線頁。此模式使用目前日期及文字設定，不使用手動聊天室或內容類型勾選；完成後也不會把聊天室全部勾上。
5. 查看來源數量、TXT 位置及「保存結果」。每筆顯示檔名、聊天室、原檔／預覽狀態與可用原因，可依狀態、名稱搜尋並換頁。若達到尋找範圍或數量上限，可批次指定其他來源。

第一次核對可能較久，可暫停或停止，不必開命令列或輸入金鑰。取得圖片影片及檔案期間需保持原 LINE 程序開啟；缺少工作階段時，可在 LINE 開啟對應檔案後重新連接，仍不保證取回成功。

## 限定來源與聊天室

按「批次選擇資料庫…」可在候選清單勾選來源，使用「全選」與「清除」，再按「批次連接」。也可在檔案視窗以 Ctrl／Shift 多選 `.edb`／`.db`，一次最多 64 份。副檔名符合不代表可讀，仍須通過金鑰、檔案識別與資料表檢查。

連接後可搜尋聊天室名稱，依類型及來源篩選，清單分頁顯示。選取操作分為「選取本頁」「取消本頁」「選取篩選結果」與「清空所有選取」；篩選及換頁不會清除已有選取，畫面會顯示已選數量。確認設定後按「保存選取的聊天室」。

每份資料庫保留自己的來源與聊天室識別，不因名稱相同、訊息 ID 相同或使用相同金鑰就合併。來源編號只供區分；可讀資料庫可能是歷史副本，**不能認定全部屬於目前登入帳號**，也不能認定其檔案可用目前工作階段取得。同一份來源再次整理，仍沿用原來識別。

## 名稱與完整訊息

聊天室及發訊者優先使用本機已有的聯絡人、本人、群組及社群名稱，依明確識別對應。資料缺名時顯示「未命名對話」或「未知成員／名稱待確認」及短序號，不將長識別碼當作人名，也不以同名推測身分。後續讀取缺名資料時，不會任意覆蓋同一身分先前已保存的可用名稱。

預設保存期間內本機可取得的完整訊息正文，不只擷取關鍵字或挑選「收藏」。名稱及檔名的顯示處理不會刪改正文。日期只限制本次讀取，不會刪除先前已保存的文字；「進階：只保存檔案，不新增文字」不會補入新訊息正文，既有正文仍保留。

## 停止與繼續閱讀

「停止並保留」會停止抓取，保留已寫入的訊息和原檔，接著整理輕量離線閱讀頁。整理閱讀頁期間仍可再次停止；即使閱讀頁未完成，已保存資料不會因此刪除。可在「保存結果」按「更新離線閱讀頁」，由現有資料重建，不必重新下載。

輕量閱讀頁會檢查基本資料關聯、本機路徑、檔案存在與大小，不假稱重新完成所有內容雜湊檢查。其檔案連結標示「開啟本機原檔」，可閱讀或預覽已保存內容；瀏覽器可能忽略本機連結的另存檔名，不能把開啟原檔當作已另存。正常完整產生的閱讀頁包含分塊下載資料，可使用原名或可讀名稱另存。需要核對整份檔案時，請在 EXE 使用「完整檢查檔案」。

離線頁保留「全部聊天室」總覽，個別聊天室的訊息、圖片影片與檔案、關聯地圖使用獨立入口；左側聊天室分頁。HTML、CSS、JavaScript 及預覽資源均在本機，不載入 CDN、遠端字型或本機伺服器。搬移或備份時需保留閱讀頁旁的檔案資料夾。

## TXT 與檔名

自動抓取與手動保存後，每個選定聊天室各產生一份 UTF-8 TXT，放在紀錄資料夾的 `text-exports/<本次匯出批次>/`。TXT 使用經安全處理的聊天室名稱，同名只加短序號；批次另有完成與校驗清單，完整內部識別留在清單，不加入使用者檔名。

TXT 包含該聊天室中已保存的對話／討論串文字、時間、發訊者、檔名及核對後的保存狀態，可能包含先前整理內容，不限本次抓取日期。原檔另存，未取得或僅有預覽會分別標示；TXT 不含登入資料、資料庫金鑰或媒體金鑰。這是聊藏產生的文字紀錄，不是操作 LINE 內建匯出。

每次匯出建立新批次，不覆寫先前 TXT；文字匯出中取消不會發布新的完成批次，已完成的舊批次仍保留。「另存完整 ZIP」不包含 `text-exports`，需保留或分享 TXT 時請另複製所需批次。

圖片、影片與檔案優先保留訊息中可用的原始檔名。沒有原名才以訊息時間及種類命名，同時點重複時加短序號；預覽另行標示，副檔名依實際內容，不把長訊息識別或雜湊當成顯示名稱。內部去重儲存路徑仍可能使用雜湊，以維持資料關聯及校驗。

## LINE 來源與儲存位置

| 畫面選擇 | 用途 |
| --- | --- |
| 自動尋找或批次選擇的 `.edb`／`.db` | LINE 已有的來源資料庫，逐份核對後唯讀開啟。 |
| 「儲存位置」 | 聊藏輸出訊息、檔案、TXT 與離線頁的資料夾。 |

不用建立新 `.db`，也不要把聊藏自己的 `archive.sqlite3` 當成 LINE 來源。來源 `.edb` 不能填進「儲存位置」。不必先下載檔案到另一資料夾；手動補入原檔不是連接資料庫的前提。

主要來源不需 `connection.local.json`、LINE 版面設定或視窗捲動。原有 UI Automation 留在進階連線頁，屬於另一條來源路徑，不能把本機資料庫測試當成它已完成適配的證據。

## 尚未另存的圖片、影片與檔案

**目前不能保證取回全部僅在 LINE 裡能開啟的內容。** 能讀取 `.edb` 不等於每一份原檔都可取得；真實 LINE 版本的工作階段、媒體金鑰及伺服器回應仍需實機驗證。

程式只讀取目前使用者、目前桌面工作階段中，簽章發行者已核對的 LINE 程序，不自動提升權限或注入。資料庫候選金鑰逐份核對；取得檔案使用匹配來源的同一 LINE 程序中具名登入資訊，不混用不同程序的金鑰或工作階段。登入資訊、資料庫金鑰、媒體金鑰只留在記憶體，不寫進設定、訊息紀錄、TXT、HTML 或診斷。

C++ 使用 Windows WinHTTP，依訊息識別、已知的 talk／社群服務格式或訊息明確提供的網址嘗試取得內容；E2EENext 使用實際服務及物件識別。所需工作階段由同一個已核對 LINE 程序取得；程序退出後不再沿用，不製造 token、不關閉 HTTPS 憑證驗證，也不使用瀏覽器 cookie。取得原檔需要網路，產生的閱讀頁可離線使用。

有可辨識的 E2EENext 媒體金鑰時，先核對完整性再以 Windows 原生加密元件解密，不拿資料庫金鑰猜圖片金鑰。

- 完整原檔：保存原始位元組、雜湊及可用預覽。
- 只有預覽：標為預覽，不當作完整原圖。
- 缺少工作階段、授權遭拒、已過期或缺少解密資訊：保留訊息，逐檔顯示未取得及可用原因。
- 部分 `.eimg` 圖片快取另有加密，尚無已驗證的完整索引與解密流程，不直接改名當作原圖。

取回失敗不代表 LINE 中的檔案已不存在，也不代表需要安裝 Python。日後若透過 LINE 另存取得原檔，可在「保存結果」按「補入圖片或檔案原檔」，選定待補紀錄與實際檔案；程式核對可用大小及內容後複製、重建閱讀頁，不會僅憑同名自動配對。

## 保存範圍與驗證界線

| 內容 | 處理方式 |
| --- | --- |
| 本機已同步的訊息 | 保存設定期間內可取得的完整原文、時間、識別與可用名稱。 |
| 圖片、影片、語音、貼圖與檔案 | 保存訊息中的資訊並嘗試取得原檔／預覽；未取得逐檔記錄。 |
| 社群討論串 | 保存範圍內回覆與原始識別，不保證取得期間外根訊息。 |
| 相簿、記事本及其留言 | 尚未涵蓋。 |
| 未同步、已過期或不在本機的歷史 | 不另外回補；本機範圍完成不代表完整 LINE 備份。 |

再次整理相同來源時依訊息識別更新，已保存且校驗通過的檔案會沿用。來源綁定資料庫位置及實際檔案識別；途中換成另一份資料庫會停止，不混入原來源。程式不修改 LINE 資料表、快取或權限。

來源依已知 Windows LINE `_chat`、`_message` 及相關表讀取，明確使用與 wxSQLite3 相容的 AES-128-CBC。LINE 更新若改變金鑰位置、加密或資料表，可能停止；讀取失敗不代表沒有訊息。

測試使用人工加密資料庫、程序候選、檔案及協定回應，涵蓋名稱、完整文字、來源隔離、選取分頁、停止保留及逐檔結果。這些不能代替真實帳號、目前 LINE 版本及「僅在 LINE 裡能開啟」內容的實機驗收。通過項目以本輪來源及 CI 為準。

訊息資料庫和原檔未加密。請勿將真實聊天照片、資料庫、程序記憶體、私人設定或檔案上傳 Git、issue 或 Release。
