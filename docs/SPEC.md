# 開發規格

## 已定案

1. 使用者啟動程式後選取聊天室，由程式取得內容，不要求使用者手動匯出聊天文字。
2. 另建獨立專案，不依賴摘要 MCP 或遠端模型。
3. 不設密碼，離線直接開啟 HTML；整包搬移後仍可查詢和另存。
4. 再次取得同一則訊息時更新目前內容，不累積重複列；索引同步更新。
5. 已保存且完整的同一附件不重新下載。新附件、僅有預覽、遺失或損毀才取得完整副本。
6. 聊天、附件、相簿、記事本、社群、子聊天室及討論串均在目標範圍內。範圍須由使用者明確選定；不自動加入社群。
7. 介面使用一般用語，所有入口都有結果、返回、空狀態及失敗處理。

## 同一筆與新版本

訊息身份以帳號、聊天室及來源訊息識別決定；暫時視窗編號、檔名、相同文字及相近時間都不是可靠身份。附件身份另含所屬項目、來源附件識別、畫質及版本資訊。若來源不提供可靠識別，就不能安全宣稱已完成更新配對。

來源明確收回或刪除的訊息改成狀態標記，舊文字退出一般頁面與索引；已存附件繼續保留。當次未讀到的資料不直接刪除。來源確認產生新的附件版本時，視為新增內容，不以舊檔冒充新檔。

## 資料關聯

每則訊息屬於有效聊天室。相簿項目屬於相簿，記事本留言屬於貼文，討論串回覆保留其父項目。附件使用有類型的來源關聯，不把相簿圖片硬塞到聊天訊息。共用檔案可對應多個有效附件紀錄。

資料庫外鍵逐連線啟用；結構檢查、外鍵檢查、實體檔案校驗及頁面導覽分開驗證。檔案與資料庫不是單一原子交易，未完成副本保留在暫存區，成功後才標成已保存。

## 完整交付門檻

自動採集、歷史範圍、訊息／引用、媒體、附件排程、增量、維護、全部來源類型、離線閱讀、安全及可執行包都須有實際流程與驗收。人工資料測試、可啟動的 GUI 或可讀的 HTML 不能替代真實 Windows LINE 驗收。

目前尚未達到完整交付門檻；不可將開發版本標為「所有 LINE 版本已支援」。每種來源都應在相容性紀錄寫出已驗證的版本、欄位、附件取得方式與未完成範圍。

## 不經遠端 Repo 的本機交付

依使用者最新決定，先完成本機程式，不建立公開 Repo。包內提供 `Start.cmd`、本機 Windows EXE 建置工具、操作說明及明確標示的人工離線範例。來源連線、Windows EXE 與多 GB 附件仍須各自通過實機門檻；來源包和人工範例不得標成已驗收完整版。

離線另存採可校驗的本機資料分段，避免 file URL 的跨來源讀檔與下載限制；原始附件二進位檔也保留。分段額外使用約原始檔大小的 4/3 空間。大檔以原生保存選擇器逐段寫入；此分支仍須 Windows 實機驗收。

## 0.3.0 使用者最新調整

正常使用改為直接開啟 Windows EXE，不要求安裝 Python。採 C++ 原生程式，保留原封存格式及更新規則。

產出的 HTML 以供人閱讀的知識地圖為主要入口：關鍵字、人物、主要內容與附件。點節點看原文，不把每則訊息全部鋪在主圖。一般閱讀與圖庫保留完整內容，正文區不呈現資料庫、識別碼或編譯說明。

圖上的字詞連結明確表示提及，不冒充語意推理；來源、人物與引用關係必須有實際依據。不確定身份的同名暱稱不得跨聊天室當成同一人。
