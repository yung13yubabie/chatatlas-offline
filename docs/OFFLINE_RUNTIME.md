# 離線執行與免安裝驗收

## 使用者實際需要什麼

- Windows 10 或更新的 x64 系統。解壓縮後直接執行 `ChatAtlas.exe`，不要求安裝 Python、Node.js、Zig、額外的 .NET 或 VC++ 套件。
- 原生程式使用 Windows 系統 DLL 與系統內建的 `winsqlite3.dll`。連接 LINE 的功能使用系統 Windows PowerShell / UI Automation；閱讀既有封存不需要連接 LINE。
- 系統元件若被企業政策停用或不存在，程式應顯示錯誤並停止該功能，不自動下載或安裝替代元件，也不要求停用防毒。
- HTML 閱讀頁以一般瀏覽器開啟本機 `index.html`；旁邊的分段資料、附件與目錄必須保留。不需要本機伺服器。

## 不屬於執行期依賴

Zig、Node.js、C++ 編譯器、Playwright 與其瀏覽器下載只用於開發、建置或 CI。它們不放進使用者 ZIP，也不由 `ChatAtlas.exe` 安裝。原始碼包中保留的歷史 Python 實作不是原生程式的啟動入口，且不由目前 CI 執行。

本版 採可攜設定：啟動會在 EXE 旁建立私人 `ChatAtlasData`，保存設定、連線設定及預設收藏／範例。原位置不可安全寫入時停止，不改用 AppData 或暫存位置；舊 AppData 不會自動遷移或刪除。這是使用者資料，不是額外套件。

原生程式沒有自動更新器或套件安裝流程。啟動原生介面與產生人工範例不應啟動其他程序；使用者選擇連接 LINE 時才啟動系統 PowerShell，選擇開啟閱讀頁時才交由預設瀏覽器處理本機檔案。PowerShell 的腳本載入不是套件安裝器。

## HTML 離線邊界

閱讀頁不使用外部 CDN、網路字型或追蹤程式。CSS、JavaScript 與圖譜邏輯隨封存提供；CSP 預設拒絕資源、拒絕 `connect-src`，只放行必要的本機腳本、圖片及媒體。瀏覽器測試應在地圖、閱讀、檔案、預覽、篩選與下載流程記錄外部請求，並測試 CSP 對注入的外部資源請求是否阻擋。

這個界線針對 ChatAtlas 閱讀頁本身，不代表作業系統、瀏覽器或既有 LINE 程式不會自行連網。將 LINE 畫面中尚未存在本機的附件下載下來，也不能稱為全程離線採集。

## 證據分層與未驗證部分

1. `native/tests/no_install_contract.cjs` 檢查指定的安裝／網路呼叫模式、動態載入及程序建立入口，並解析交付 EXE 的 PE 匯入表。新增入口或非預期 DLL 必須重新檢視。通過不是所有行為均已證明安全。
2. `native/tests/no_install_runtime.ps1` 把單一 EXE 複製到空資料夾，清除子程序開發環境變數，PATH 只保留 Windows System32，分開執行兩組檢查：命令列人工範例／完整性檢查，以及無參數的原生 GUI 啟動。GUI 必須產生預期的主視窗 HWND／標題、維持運作並正常關閉；未能取得視窗視為失敗，不算跳過通過。測試會抽樣檢查直接子程序，但不是完整程序追蹤。此測試不下載或安裝任何工具，不操作真實 LINE。本版 使用 `ATLAS_PORTABLE=1` 的驗收模式，另核對 EXE 旁資料、搬移重開、舊 AppData 未變及唯讀停止；未開啟此驗收模式只為保留 alpha.2 歷史截圖工作的相容性，不是 本版 程式的儲存位置開關。
3. 瀏覽器回歸測試檢查本機 HTML 的操作與外部請求；成功只涵蓋實際執行過的流程。
4. GitHub hosted runner 本來就有其他軟體。即使隔離 PATH 的測試通過，也不能當成全新 Windows 安裝、企業受管環境或所有 GUI 流程的驗收。真正乾淨 Windows 上的首次啟動、GUI 按鈕完整操作與 LINE 全流程仍需另外實測；不能標成「100% 無依賴／完全離線／無暗門」。

每次發布應以該版本的精確 commit、建置資產與 CI 結果判斷，不沿用前一版通過記錄。

## 儲存媒體與雲端同步

工作收藏與可攜設定需要可驗證的私人 ACL。偵測到 reparse 標記時仍保守拒絕，不概括放行所有雲端標記；這不代表每個 OneDrive 桌面必然不支援。

匯出 ZIP 和開啟工作收藏是不同路徑。ZIP 父目錄沒有必須私人 ACL 的程式規則；仍受實際寫入權限、連結檢查、空間及檔案系統限制影響。FAT32 約 4 GiB 單檔限制不會因 ZIP64 而消失。無持久 ACL 的媒體不能提供同樣的帳號權限保護，匯出的 ZIP 本身也沒有加密。exFAT／FAT32 實體媒體仍需另行驗收。
