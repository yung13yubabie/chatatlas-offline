# alpha.7 核對與修正範圍

本輪基準為 alpha.6 發布來源 `d8a867825c096a55799017edcd0de61d70ee0b8f`，以及只訂正兩個 README 證據連結的 main `8c224348d5c3e8d1154af074fdebcd11ebfd0d3a`。先核對問題，再只修改成立的行為與必要測試。

## 核對結果與修正

1. **GUI 捲動重繪**：來源缺少父視窗 `WS_CLIPCHILDREN`，layout 對各控制項逐一同步重繪。本輪改為整批移動後統一重繪，保留捲軸、焦點露出、DPI 與既有頁籤動線。原生控制項測試與實際截圖仍需 Windows CI；`PrintWindow` 會觸發繪製，截圖不能單獨證明所有桌面合成殘影均消失。
2. **網路私人儲存**：來源使用本機 process token SID 建立保護 DACL，但只檢查磁碟可用 ACL，沒有排除遠端位置。SMB 登入身分可能不同，是已確認的來源邊界缺口；使用者目錄的實際 ACL／鎖定狀態尚未取得，不能斷定現場刪除失敗一定由此造成。本輪在所有私人目錄／檔案建立入口先做本機路徑與磁碟檢查，涵蓋 GUI、CLI、匯入目的地、鎖檔與 ZIP。UNC、延伸 UNC、映射遠端與無法確認的磁碟拒絕，不放寬既有本機 ACL 或 handle 檢查。外部備份唯讀來源不因這道私人寫入檢查而禁用。
3. **雲端／連結提示**：原策略刻意拒絕重解析點，並非本輪允許 OneDrive；只改善移到一般本機目錄的指引，不把任意重解析點誤稱為 OneDrive。
4. **LINE 主視窗診斷**：零個和多個候選視窗原本共用 ambiguous 錯誤；現在獨立 missing 代碼、白名單與原生提示。零個也可能是系統匣狀態，不等於已證明 LINE 未安裝。合成測試不連接真實 LINE。
5. **資料目錄入口**：增加「開啟 ChatAtlasData」並處理系統無法開啟的回應；只是開啟既有資料目錄，不代替使用者刪除、取得所有權或更改權限。
6. **連線設定指引**：本版仍不隨附已驗證的私人版面設定。無設定只做 probe；指引載入設定時仍明示必須符合實際 LINE 版本，不能把載入成功等同採集驗證。
7. **README 證據**：alpha.6 source ZIP 保留兩個舊連結是凍結產物勘誤；main 已訂正，本輪承接修正，不重包或替換 alpha.6 資產。
8. **歷史時間**：顯示轉成 UTC+8，資料庫時間／篩選契約不變；測試涵蓋日期跨界、偏移與不合法時間，不用字串直接加八小時。

## 驗證與發布規則

- 精確提交的 Linux、Windows、離線 Chromium 與實際封裝 EXE 檢查分開列示。
- 新增本機私人路徑純契約與 Windows 檔案建立入口測試；合成 UNC 拒絕不是對實際 SMB／NAS ACL 的完整驗收。
- 公開檔案掃描、版本／manifest／資源一致性及內嵌 PowerShell 重建必須通過。
- README 圖片只用實際執行產物，標明版本、來源與合成資料，不把舊圖改名假裝新圖。
- 最終四個 Release 檔案只使用同次已驗證 CI 的原始位元組及來源證明。

## 未解決的現場與驗收界線

本輪預防新的不安全遠端私人建立，**不會自動修復共用端已存在、無法刪除的資料夾**。既有目錄仍需先確認程序是否關閉、正確 SMB 帳號、分享與檔案權限，再由有權管理者處理指定目錄；不建議整個共用磁碟 Everyone 全控制。

真實 LINE 完整採集、使用者現場 SMB／NAS、實體多螢幕合成、全 Windows／瀏覽器矩陣仍未通過完整驗收。EXE 尚未簽章，CFG 未啟用；不宣稱無漏洞、無後門或絕對不外連。
